# Security Policy

## Supported version

Security fixes currently target the latest code on `main` while My GitLife is in its initial public stage.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting option on the repository's **Security** tab when it is available. Include reproduction steps, affected versions, and impact, but do not include real access tokens or private repository data.

If private vulnerability reporting is unavailable, open a public issue requesting private reporting instructions without disclosing vulnerability details. Repository-specific reporting instructions will then be provided through GitHub.

Please do not publish an unresolved vulnerability or test against accounts and repositories you do not control.

## Data boundary

My GitLife is designed to analyze public GitHub profile, repository, language, and event data only. Reports involving private-data exposure, token disclosure, unsafe avatar content, path traversal, or unsafe file overwrite behavior are treated as security issues.
